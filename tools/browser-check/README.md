# Browser check

Quick manual checks of the built app in headless Chrome. Automated Chromium tests also run in Pages CI.

```sh
(cd app && npm run build)
tools/browser-check/start.sh
node tools/browser-check/cdp.mjs shot 9333 /tmp/ui.png 1280 800
node tools/browser-check/cdp.mjs eval 9333 "document.querySelector('.status-bar').innerText"
tools/browser-check/stop.sh
```

The `shot` command can run a script before the screenshot, e.g. to open a menu:

```sh
node tools/browser-check/cdp.mjs shot 9333 /tmp/menu.png 1100 420 \
  "[...document.querySelectorAll('.menu__button')].find(b => b.textContent === 'Tools').click()" 500
```

Note: `--dump-dom` and `--virtual-time-budget` do not wait for the compute worker; use these
scripts, which wait in real time. To set an input value from a script, use the native setter so
React sees the change:
`Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set.call(input, '42')`,
then dispatch an `input` event and blur the field.


## Real-engine UI timing

After building the WASM core in `build/wasm`, run from the repository root:

```sh
node app/scripts/test-real-ui.mjs
```

An optional argument selects another directory containing `remagx-core.mjs` and
`remagx-core.wasm`. The script builds the complete app in `build/real-ui-test`,
substitutes the real service factory only in that test build, and serves those
static assets locally. It does not change `app/dist` or the deployed engine.

The synthetic fixture is generated by the native WASM engine, not the mock. Tests
check visible fit progress and preview, tab response below 200 ms, Stop below 1 s,
absence of redraw requests behind a running fit, and recovery after blocked
fit/reflectivity/chi-square workers. The existing `test-real-service.mjs` checks
numerics and worker integration separately. These timing checks do not establish
original-optimizer fit quality or full engine acceptance.

The isolated Lua worker check uses the same `build/wasm` core files and the
installed Wasmoon package:

```sh
node app/scripts/test-lua-runtime.mjs
```

It stages locally hosted Lua and numerical WASM assets, verifies that no external
runtime requests occur, and exercises array/element userdata, source-line errors,
session isolation and native `element:setf` interpolation. It does not yet run
whole-project legacy scripts or establish AC-7/AC-8 acceptance.
